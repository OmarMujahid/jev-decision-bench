# jev-decision-bench

An independent benchmark of [TypeSafe's Jev](https://docs.typesafe.ai/), a model that does not write text. You send it some content and a list of typed questions (yes/no, pick one option, rate on a scale) and it returns probabilities.

This repo asks: how good are those decisions, compared with a small fast LLM given the exact same questions?

- 49 tasks, 8,225 items
- Labels come from public human-labelled datasets, or from code for the synthetic probes
- Same question wording for every model
- Python standard library only, no dependencies

I have no affiliation with TypeSafe. Run date: 18 September 2026, model `jev-1.13.0`.

## Results in short

Baseline is `gpt-5.6-luna` with reasoning off (`luna`) and with reasoning set to low (`luna-low`).

| | Jev | luna | luna-low |
|---|---|---|---|
| Tasks where Jev scored higher / tied / lower than the better baseline | 32 / 10 / 7 | | |
| Median server time per item | 105 ms | 710 ms | 808 ms |
| Cost per 1,000 items | $0.04 | $0.16 | $0.19 |
| Calibration error (ECE, lower is better) | 0.07 | 0.18 | 0.14 |

## Read this before quoting the numbers

- Most tasks are well-known public benchmarks. Any model may have seen them in training. The only contamination control here is `fresh_math`, 120 word problems generated by code; Jev scored about the same there as on GSM8K.
- The baseline was deliberately held to no or low reasoning, because the comparison is about fast decisions. With more reasoning an LLM will score higher on the reasoning tasks and take seconds per item.
- 200 items per task gives intervals of roughly ±0.05. Only six Jev leads clear both baseline intervals (TruthfulQA, ARC-Challenge, HellaSwag, LogiQA, WinoGrande, two-hop). The baseline has one such lead (counting).
- The baseline's probabilities are numbers it writes into JSON. Jev's come from its output distribution. That is the fairest comparison available, not an equal one.
- Latency is server processing time from response headers (`x-envoy-upstream-service-time`, `openai-processing-ms`). Network time is extra. TypeSafe's endpoint was in a US region at the time.
- Several probes were too easy to tell models apart: needle-in-a-haystack up to 22k tokens, number and date comparison, double negation. Everyone scored near 1.0.
- Clean benchmarks hide some things. In a separate private test with around 100 long documents per request, Jev gave high relevance scores to a handful of plainly unrelated documents. Nothing in this repo reproduces that.
- Jev cannot write text, call tools or explain an answer. This measures decisions only.

## What is measured

| Category | Tasks |
|---|---|
| Classification | SST-2, SMS spam, Civil Comments toxicity, AG News, Banking77, TREC, Emotion, language ID |
| Reading and inference | BoolQ, MNLI, PAWS |
| Extraction by selection | SQuAD answer sentence, CoNLL-2003 entity typing, numeric/date value selection |
| Graded scoring | STS-B, Yelp stars, HelpSteer2 helpfulness |
| Reranking | MS MARCO, NFCorpus |
| Knowledge | MMLU, TruthfulQA MC1 |
| Reasoning | ARC-Challenge, CommonsenseQA, HellaSwag, WinoGrande, ANLI R3, LogiQA |
| Multilingual | XNLI (same 150 items in en, ar, fr, zh, hi, sw), Arabic sentiment |
| Long input | one planted fact in 1k / 4k / 12k / 22k tokens of filler |
| Robustness | injected instructions, a question and its negation, four wordings of one task |
| Vendor-listed weak spots | counting, number and date comparison, two-hop facts, double negation, GSM8K as multiple choice, fresh math |

Per task: a primary metric with a bootstrap 95% interval (accuracy, AUROC, Spearman, MRR or nDCG@10), plus calibration error, accuracy on the most confident 80% and 50% of answers, median latency, tokens and cost.

## Run it

```bash
python3 build_tasks.py          # builds tasks/ from public datasets, cached in .cache/
export TYPESAFE_API_KEY=...
export OPENAI_API_KEY=...
python3 run.py jev              # or: luna, luna-low, openai:<model>[:<effort>]
python3 run.py jev sst2 mmlu    # only some tasks
python3 metrics.py              # writes report.json and RESULTS.md
```

- `build_tasks.py` pulls rows from the Hugging Face datasets-server, which rate-limits anonymous callers, so the first build is slow (tens of minutes). Sampling is seeded, so you get the same items I did.
- `run.py` appends each answer to `results/<model>/<task>.jsonl` as it arrives. If it stops, run it again and it continues.
- A full Jev run cost me about $0.31, a full `luna` run about $1.30.
- `results/` holds my raw per-item predictions, so you can re-score without calling any API once `tasks/` is built.

## Task files are not in the repo

`tasks/` is git-ignored. The source datasets have different licences and some do not allow redistribution, so the repo ships the builder scripts instead of the data. Check each dataset's licence before you publish anything built from it.

## Add a task or a model

- A task is one JSON file. The format is in [SPEC.md](SPEC.md). Add a builder under `builders/`, then `python3 validate.py tasks/<id>.json`.
- The builders never call a model, and the question wording was written once and not tuned against results. Please keep it that way.
- A model is one function in `run.py` that takes `(state, questions)` and returns a prediction per question: `{"p": ...}` for yes/no, `{"choice": ..., "conf": ...}` for pick-one, `{"score": ...}` for a scale.
